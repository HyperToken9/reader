# PROTOTYPE 48 — Kokoro on WebGPU in an MV3 offscreen document (throwaway)

For [#48](https://github.com/HyperToken9/reader/issues/48) on map [#43](https://github.com/HyperToken9/reader/issues/43). Throwaway code; the answer is in the issue comment and in `RESULTS` below.

## What is here

- `extension/` — an unpacked MV3 extension.
  - `sw.js` owns the offscreen document and relays offscreen → tab messages.
  - `offscreen.js` runs Blitz's own engine on onnxruntime-web 1.31.1 (WebGPU EP, WASM fallback), with the model downloaded once into Cache Storage. It plays the audio on an `AudioContext` and sends per-sentence word spans (from `duration`) plus a 1 s clock tick to the tab.
  - `content.js` keeps the word cursor on the page's own clock and logs what it showed and when.
  - `engine.browser.js` / `phonemize.browser.js` are generated by `scripts/make_browser.mjs` from `app/electron/speech/{engine,phonemize}.js` on `origin/dev`: only the imports, `loadVoices(bytes)` and the session options change. Windows, pauses, durations → spans, alignment are byte-for-byte the app's.
  - `manifest.json` sets `wasm-unsafe-eval`, `unlimitedStorage`, and COEP/COOP so the offscreen document is cross-origin isolated (WASM threads).
- `scripts/ref_node.mjs` — the reference: the app's Node engine (onnxruntime-node 1.23.2, CPU, 4 threads) over prototype 17's `corpus/sentences.json`, plus espeak-ng 1.52 phonemes for every sentence and word.
- `scripts/run.mjs` — the harness: its own Chrome 157 with a throwaway profile under the job tmp dir, the extension loaded through CDP, one experiment per call (`bench`, `durations`, `ttfa`, `drift`, `survive`, `phon`, `coi`).
- `scripts/gpu_probe.mjs` — WebGPU availability per flag set, headless and headed.
- `out/*.json` — results (big per-sentence dumps are not committed).

## Run

```sh
./setup.sh                         # ref/ from origin/dev, npm install, generate + vendor into extension/
node scripts/ref_node.mjs 4 3      # reference
node scripts/gpu_probe.mjs headless angle_vk_native
node scripts/run.mjs bench --ep webgpu --pp low-power --reps 3
node scripts/run.mjs durations --ep webgpu --pp low-power
node scripts/run.mjs ttfa --ep webgpu --pp low-power --profile ttfa
node scripts/run.mjs drift --ep webgpu --pp low-power
node scripts/run.mjs survive --reasons AUDIO_PLAYBACK --pause 35
node scripts/run.mjs phon
```

Every timed run was wrapped in `flock /home/homefree/.claude/jobs/ec2bb647/tmp/bench.lock` (shared with prototype 47) and records `uptime`.

## Results (2026-11-10)

Machine: Ryzen 7 5800H (16 threads), AMD Radeon iGPU (Renoir, RADV) and NVIDIA RTX 3060 Laptop (driver 595), Linux X11, Google Chrome 157.0.8103.50. **Headless** (`--headless=new`) for every number below; headed was probed for WebGPU only. The machine was shared and not idle: load averages are in every `out/*.json`.

| metric | result |
|---|---|
| WebGPU available? | **Only with flags.** Stock Chrome: `requestAdapter()` → `null` (headed) or SwiftShader software only (headless). Headed needs `--enable-unsafe-webgpu --enable-features=Vulkan`. Headless needs those plus `--use-angle=vulkan --use-vulkan=native`. |
| GPU | `high-performance` = NVIDIA RTX 3060: **no `shader-f16`** in Chrome, so Blitz's fp16 graph fails (`Cast requires f16`). `low-power` = AMD Radeon iGPU (gcn-5): has `shader-f16`, works. All numbers are the iGPU. onnxruntime-web 1.31's EP picks the default (NVIDIA) adapter unless you hand it a `GPUDevice`. One of six iGPU runs still hit the f16 error, cause not found. |
| warm RTF (6 bench sentences, full engine) | **WebGPU iGPU 0.176 / 0.176 / 0.176** (load 3.2). It was 0.252 / 0.245 / 0.238 at load 16. WASM, 4 threads, in Chrome: 0.907 / 0.902 / 0.908. Node engine reference: 0.353 / 0.350 / 0.350 (load 7). |
| TTFA cold (fresh profile, model fetched from localhost into Cache Storage) | **5.4 s.** That is 0.4 s fetch, 0.5 s cache put, 2.7 s session, 1.3 s first synth. A real first download of 192 MB from GitHub adds its network time. |
| TTFA after a Chrome restart (model in Cache Storage) | 4.2 s (0.24 s cache read, 2.7 s session, 1.0 s synth) |
| TTFA warm (offscreen alive, 37-char sentence) | **0.64 / 1.07 / 0.67 s** (load 7–9) |
| `duration` exact vs Node engine? | **No.** WebGPU matches on 94/206 sentences. 27830/28019 tokens are identical in same-shape runs, and max ±4 frames. Spans are identical on 84/206 and the word grouping is the same on 206/206. Span edges move p50 25 ms, p95 115 ms, max 315 ms. WASM (ort-web 1.31 vs Node's 1.23.2) is not exact either: 182/206, max ±1 frame, p95 25 ms. |
| clock drift, 2-min passage (134.7 s, 13 sentences, 364 words) | Audio clock vs system clock: **−3.7 ms over 129 s.** Offscreen→SW→tab latency: p50 1.2 ms, max 9.6 ms. Page cursor vs audio: p50 1.6 ms, max 4.8 ms. First 30 s mean 1.4 ms, last 30 s 0.4 ms: no growth. No underruns. |
| cross-origin isolated? | **Yes** with `cross_origin_embedder_policy: require-corp` + `cross_origin_opener_policy: same-origin` in the manifest: 4 WASM threads. Without them, `crossOriginIsolated` is false, so 1 thread. |
| offscreen survives 30 s / 5 min pause? | `[AUDIO_PLAYBACK]` alone: **closed 15–20 s after audio stopped.** Resume reloads everything, 5.9 s to audio. `[AUDIO_PLAYBACK, WORKERS]`: **alive at 30 s and at 305 s**, the same document, resume 1.7 s. Caveat: run with `--mute-audio`. |
| RAM | WebGPU: 1155 MB PSS for the whole Chrome. Of that, the extension renderer is 670 MB and the GPU process 224 MB. `measureUserAgentSpecificMemory` gives 465 MB. WASM: 1465 MB (extension renderer 1026 MB). |
| GPU memory | iGPU (amdgpu fdinfo): 550 MB VRAM (carved-out) + 141 MB GTT after the bench. NVIDIA: 7 MB (unused). |

Phonemes in the browser, measured against espeak-ng 1.52 over the same 206 sentences and 3969 words:

| phonemizer (in the offscreen document) | sentences | words |
|---|---|---|
| npm `phonemizer` 1.2.1 + Blitz's punctuation port | 151/206 (73.3%) | 2795/3969 (70.4%) |
| kokoro-js 1.2.1 `phonemize()` | 108/206 (52.4%) | 2679/3969 (67.5%) |

So prototype 17's 73% holds in the browser. Every timing and durations comparison above fed Node espeak-ng phonemes, to isolate the model.

Not measured: WASM TTFA, the fp32 model on NVIDIA (it also failed at `OrtRun`; the error was not captured), WASM at 1 thread, headed timings, and a real network download.

**espeak-ng 1.52 via emscripten (estimated, not built):**
- **Work:**
  - a native build of 1.52 first, to compile `phondata` and `en_dict`;
  - `emconfigure`/`emmake` of `libespeak-ng` with no audio output;
  - about 30 lines of C glue exporting `espeak_Initialize`, `espeak_SetVoiceByName` and `espeak_TextToPhonemes` (upstream's glue only exposes trace-IPA synthesis);
  - English-only `espeak-ng-data`, about 1.5 MB (0.6 MB xz, per prototype 17), into MEMFS.
- **Reuse:** `makePhonemize(raw)` from `app/electron/speech/phonemize.js` works unchanged with a sync `raw`.
- **Check:** prototype 17's 206-sentence parity test.
- **Estimate:** 1–2 days if autotools cooperates, plus 1–2 days for a reproducible build in CI. About 0.5 MB of WASM plus 1.5 MB of data, GPL-3.0 as now.
- **Risk:** low for parity, since it is the same C code and data. Most of the effort is the build plumbing.
